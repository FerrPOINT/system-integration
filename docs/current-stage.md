## Рабочая среда и версия

Рабочий каталог — `/opt/dev/system-integration` на `firebat1`.
Frontend опубликован из 3cc114c; backend и эмулятор — из bbe99ba.
На bbe99ba выполнены серверные проверки (41 тест) и нагрузочный NF08; после этого backend
и контракты не менялись. Итоговые 40 браузерных сценариев, пять тестов клиента,
production-сборка и публичный HTTPS проверены для frontend 3cc114c.
PostgreSQL сохранил контейнер и данные.
Восстановление и чистый запуск ранее проверены на 6c2fd5d; для текущего изменения
они не повторялись, их отчёты относятся к прежней версии.
Код и все 19 Markdown-документов сохранены в GitHub, исходное ТЗ не изменялось.

Публичный вход: Koara TLS gateway → ограниченный обратный SSH-туннель →
frontend Firebat1. Публичный Compose включает Secure cookie и restart policy.
Порты `19573`, `19580`, `19581` и `19532` на Firebat1 слушают только loopback;
порт туннеля на Koara тоже привязан к loopback. БД, API эмулятора и команды
сбоев наружу не маршрутизируются. Команды находятся в [README](../README.md#публичный-стенд).

## Темы и удобство интерфейса

Тёмная тема включается при первом запуске; светлая и серая доступны в шапке
и на экране входа. Выбор сохраняется в браузере, синхронизируется между вкладками
и не сбрасывается после выхода. Контраст ключевых элементов входа проверен
автоматически. Мобильная шапка, карточки, сворачиваемые фильтры, история
и экран сверки проверены через IAB. Цветовые токены и используемые Button, Input, Textarea, Select и Badge
перенесены из Base локально. Карточки, заголовки, поля с подсказками, таблица,
сообщения, фильтры и история теперь используют общие Card, PageHeader,
FormField, Table, Notice, Disclosure и Timeline. Общими стилями владеет ui/,
Brand один для входа и шапки: Base IconMark с SVG ArrowRightLeft.
Страница входа использует компактную общую карточку без отдельного псевдологотипа.
Select использует Radix, отправка FormData и required сохраняются.
На публичном экране 390 px меню всех трёх тем помещается по ширине;
отступ стрелки от края — 17 px вместе с рамкой. Происхождение и адаптация
указаны в [описании UI](../frontend/src/ui/README.md).

## Вертикальные интервалы

У всех экранов один владелец внешних интервалов — родительский base-page-stack
с gap 20 px. Убраны дублирующие margin заголовка, фильтров, пагинации, истории,
форм и сетки сверки. Связанные метаданные сгруппированы с интервалом 4 px.
Loading использует локальное представление Base LoadingState без иконки Notice.
До исправления UI-07 фиксировал 0 px между фильтром и загрузкой; после исправления
UI-07/UI-08 проходят на 390 и 1440 px. Они удерживают HTTP-ответ в тестовом браузере.
Снимки загрузки лежат в результатах Playwright; публичный IAB проверяет фактические
интервалы готовой страницы отдельно.

## Пагинация, фильтры и повторные запросы

Общие списки показывают номера страниц, их общее число и количество записей.
Мобильная версия использует компактное окно из трёх номеров. Итоги учитывают
права и фильтры; подсчёт и выборка используют один снимок БД. Несуществующая
страница предлагает переход к доступной. Фильтры применяются сразу, сбрасывают
страницу и остаются в URL; неверный период объясняется до запроса.
Кнопка «Применить» удалена, изменение фильтров не закрывает их и не теряет фокус.

Устаревшие чтения отменяются. При смене пользователя или роли приложение
очищает приватный кэш до показа новой сессии и сбрасывает состояние оболочки.
UI-11 сначала воспроизвёл старую карточку после смены аккаунта, затем прошёл
для другого пользователя и повторного входа того же владельца.
Повтор команды после потерянного HTTP-ответа сохраняет ключ и исходный результат;
UI-10 проверяет один созданный объект и обновление списка.
Серверный кэш списков не добавлялся: результаты NF08 укладываются в требования.
Правила владения кэшем и идемпотентности описаны в [архитектуре](architecture.md#чтение-кэш-и-повтор-команд).

На публичном IAB проверены мобильные карточки и пагинация при 390 px,
настольная пагинация, сохранение фильтра при переходе, отсутствие переполнения
и выбранная серая тема. Хеш публичного JavaScript совпал с файлом образа 3cc114c.
Все семь контейнеров Films Manager и PostgreSQL приложения сохранили ID, образ
и время запуска относительно начала работ.

## Вывод Mini-CRM из эксплуатации

На Firebat1 удалены прежний checkout `/opt/dev/projects/mini-crm`, два тома БД,
старый tunnel unit и его три SSH key/known-hosts файла. На Koara удалены прежняя
учётка туннеля, её home и sshd-конфигурация, старый Nginx vhost.
Исходники Mini-CRM сохранены в прежнем GitHub-репозитории на `167403d`.

Действующий Xray читает сертификат домена из `/etc/xray/tls/mini-crm`;
этот runtime-каталог сохранён. Certbot обновляет его через
`/etc/letsencrypt/renewal-hooks/deploy/demo-certificate`. Общий Xray
не перезапускался. У нового приложения собственные учётка, ключ и unit туннеля.
