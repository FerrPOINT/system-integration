## Архитектура и границы

Один backend, отдельный эмулятор и две прикладные БД в одном PostgreSQL.
Spring Data JDBC обслуживает обычные чтения. Команды, блокировки, очередь и
квитанции используют явный JDBC. Сетевой вызов выполняется между транзакциями.
Пять автоматических вызовов на серию ограничивают доставку. Новую серию
оператор разрешает по свежей сверке с тем же ID операции.

## Нагрузка

В каждом профиле было 5 000 исходных записей, 20 клиентов, 30 секунд прогрева
и 120 секунд измерения. Четыре операции API выполнялись в пределах
2 CPU / 4 ГиБ суммарно, включая frontend. Пороги ТЗ для p95 — 2 с на чтение
и 3 с на изменение.

| Версия и маршрут генератора | Запросы / ошибок | p95 чтение / изменение, мс | p95 от создания до исполнения | Итоговая сверка |
| --- | ---: | ---: | ---: | ---: |
| `304d73c`, Firebat1 → localhost API | 52 834 / 0 | 98,25 / 98,37 | 63,31 с | 20 368 записей |
| `3f4e386`, Windows → SSH → тестовый API Firebat1 | 57 348 / 0 | 110,16 / 120,03 | 0,793 с | 21 389 записей |

Очередь опустела в обоих прогонах. Сверка подтвердила отсутствие потерь и
повторного исполнения. Public HTTPS и браузер не входили в измерение.
Задержка исполнения относится к конкретному прогону и измеряется отдельно
от ответа API. Методика и команды находятся в [NF08](../tests/load/README.md).

Mixed, capacity и steady — отдельные исследования с собственными условиями
в [журнале](exchange-performance-plan.md). Результаты 70×4 не подтвердили
устойчивость.

## Ограничения

- Проверены одиночная установка и профиль NF08. Несколько реплик, HA и
  непрерывная нагрузка сверх профиля остаются вне проверенного объёма.
- COUNT растёт с количеством подходящих записей. Idle timeout ограничивает
  бездействие в транзакции, активный SQL может ждать освобождения блокировки.
- При ошибке всей страницы курсор сохраняется. Чтение возобновляется после
  исправления источника и перезапуска backend.
- После перезапуска backend требуется повторный вход. Для работы сессии
  нужен современный браузер с Web Locks и HTTPS либо loopback.
- [Скан базовых Java-образов](general-audit.md) относится к прежнему кандидату.
  PR #24 убирает `pebble` из файловой системы новых контейнеров. Исходный
  бинарник остаётся в базовом слое OCI.
