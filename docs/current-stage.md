## Spring-слои — реализация

Выделены controller, service, repository/jdbc, domain, dto, mapper, client/http,
security, scheduler, config и exception. Технический json/ContentFingerprint
имеет двух действующих потребителей: квитанции и диагностику; обратной
зависимости JDBC от service нет. Подробности — в [архитектуре](architecture.md#границы-кода).

TaskRepository и ExchangeRepository имеют отдельные JDBC-реализации и общий
TaskRowMapper. IdempotencyService координирует lock/read/callback/save в
транзакции вызывающего сценария; репозиторий квитанций выполняет только SQL.
Сверка сохраняет два существующих bean: HTTP в ReconciliationService между
prepare/save-транзакциями ReviewService. Новые процессы, JPA, Redis и брокер
не добавлялись.

TaskApiMapper, ReviewApiMapper и OperationApiMapper — реальные MapStruct
Spring beans. Lombok используется для простого DI и логирования; валидирующие
конструкторы остаются явными. Generated находится только в build.
Annotation processors отсутствуют в runtime JAR.
