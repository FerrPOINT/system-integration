## Архитектура и границы

Два Spring Boot приложения, PostgreSQL и React frontend. Domain остаётся без
Spring/JDBC/generated DTO; service владеет правами и транзакцией, controller/mapper —
HTTP. Spring Data JDBC читает карточки/реестр/историю; командный SQL и обмен
остаются в JDBC-репозиториях. Generated interfaces/client/text constraints
появляются только в build. Новый TextRule обслуживает существующие title/reason.

Очередь владеет расписанием; сеть выполняется вне транзакции. Сохраняются
пять попыток в серии, leases/fencing, атомарность outbox/history/receipt и
применения страницы с курсором. Нет новых процессов, кэшей, партиций или
параллельной legacy-реализации.

## Ограничения

- NF08 измеряет HTTP-принятие, а не обещание немедленного внешнего исполнения.
  При интенсивном closed-loop потоке первое отправление p95 70,73 с;
  затем очередь полностью обработана. Устойчивость проверяется отдельным mixed.
- Точный предел мощности и неограниченный рост базы не установлены.
  COUNT остаётся линейной работой; исторические результаты 90 не стали гарантией.
- Idle timeout защищает только бездействие внутри транзакции. Активный SQL
  может ждать внешнюю блокировку до её освобождения: общего SQL-бюджета нет.
- Закрытие общей проблемы не чинит источник и не снимает invalid-page pause.
  Исправить источник, затем перезапустить backend worker; курсор сохраняется.
- OS-скан контейнеров из предыдущего цикла не объявляется новой проверкой:
  его 30 Medium / 4 Low без исправления на тот момент не считаются устранёнными.
- Новые образы не установлены в публичное demo. Свои QA-контейнеры/том/сеть
  удалены; 11 обычных контейнеров сохранили ID/image/StartedAt. Исследовательские
  заметки performance-options.md восстановлены с проверкой SHA и не входят в PR.
