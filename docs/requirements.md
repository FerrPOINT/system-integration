# Требования и критерии приёмки

Источник — [ТЗ версии 2.1](original-specification.md). Таблица связывает
обязательные пункты с наблюдаемым результатом и [сценариями проверки](test-cases.md).
Принятые бизнес-правила описаны в [аналитике](analysis.md).

| ID | Критерий приёмки | Проверка |
| --- | --- | --- |
| D01 | Инициатор получает ID сохранённого задания при недоступном исполнителе. Подтверждение приёма меняет состояние доставки. Итог исполнения приходит отдельно. | TC-01, TC-05 |
| D02 | Обе стороны соблюдают один контракт, используют неизменный ID операции и одинаково трактуют применимость результата. Генерация интерфейсов и клиента проверяется отдельно от обмена. | TC-03, TC-04, TC-15 |
| D03 | Потеря ответа и повтор отправки дают ровно одно внешнее исполнение. Дубликат результата не меняет бизнес-состояние, запоздалый снимок не откатывает его. | TC-03, TC-04 |
| D04 | Ожидающий обмен возобновляется после перезапуска и восстановления доступности, включая длительный простой. Временные ошибки повторяются по единому расписанию, неверное сообщение попадает на разбор. | TC-05, TC-06 |
| D05 | Оператор видит неопределённый исход и результат сверки. Расхождение сохраняется, решение имеет причину и автора. | TC-03, TC-07 |
| D06 | Интерфейс показывает задания, историю, проблемы и сверку. Оператор может выполнить допустимый повтор. Инициатор видит только свои записи. | TC-07, TC-08, TC-09 |
| D07 | Четыре режима отказа воспроизводятся командами эмулятора. Его фактическое состояние и счётчик исполнений доступны независимо от приложения. | TC-03, TC-04, TC-05, TC-10 |
| NF01 | Веб-интерфейс показывает данные API и PostgreSQL. Ограничения действуют при прямом запросе. | TC-01, TC-08, TC-09 |
| NF02 | Два инициатора и оператор входят под демоучётками. Смена ID и прямой вызов операторской команды не расширяют доступ. | TC-08 |
| NF03 | Перезапуск приложения и БД сохраняет принятые изменения. Ошибка внутри операции откатывает все её изменения. Параллельная запись со старой версией отклоняется. | TC-05, TC-11 |
| NF04 | Повтор команды с тем же ключом и содержимым возвращает прежний результат. Иное содержимое с тем же ключом отклоняется. Разные действия выполняются независимо. | TC-02 |
| NF05 | История сохраняет автора, время, объект и содержание изменения. При передаче разбора между операторами видно, кто был и кто стал ответственным. Права чтения и авторство старых событий сохраняются после передачи, смены состояния и перезапуска. | TC-05, TC-07, TC-08, TC-14 |
| NF06 | Сценарий выполняется от 390 до 1440 px, в том числе с клавиатуры. У полей есть подписи, у запросов — состояния загрузки, пустого результата и ошибки. | TC-09 |
| NF07 | API, UI и фильтры используют UTC. Начало периода включено, конец исключён. Правило просрочки применяется одинаково в API и UI при наличии срока. | TC-12 |
| NF08 | При 5 000 исходных записях и 20 клиентах p95 чтения ≤ 2 с, изменения ≤ 3 с в пределах 2 логических ядер и 4 ГиБ для API, БД и эмулятора. Прогон включает штатные бизнес-команды. | TC-13 |
| NF09 | Из чистого checkout по инструкции поднимаются зависимости, схемы и демоданные. Платные сервисы не нужны. | TC-10 |
| NF10 | Автоматические тесты покрывают правила, права, повторы и конкуренцию. Проверки с PostgreSQL используют настоящую тестовую БД. Журнал пригоден для диагностики и не содержит паролей или ключей. | TC-02, TC-06, TC-08, TC-11, TC-14 |
| D-NF01 | После перезапуска и восстановления связи сохранённый обмен продолжается, включая отложенные попытки. Приём сообщения и итог исполнения различимы. | TC-01, TC-05, TC-06 |
| D-NF02 | Счётчик исполнения после повторов и потери ответа равен одному. Состояние после дубликата и позднего сообщения совпадает с последним применённым. | TC-03, TC-04 |
| D-NF03 | Максимум пять автоматических вызовов на серию; затем управляемая остановка. Новая серия — после свежей сверки и решения оператора. Ошибки различимы, история связывает задание, попытки, внешний результат и решение. | TC-06, TC-07 |

## Публикация по поручению владельца

Дополнение от 12 ноября 2026 года: System Integration работает по
`https://demo.azhukov-dev.ru` вместо Mini-CRM. TLS, защищённая сессия,
доступ обеих ролей и выдаваемый JavaScript проверяются через публичный адрес
по TC-16. Эмулятор, его команды сбоев и PostgreSQL остаются на loopback.
Серверные ресурсы Mini-CRM удаляются после проверки нового приложения;
его исходники сохраняются в прежнем GitHub-репозитории. Соседние приложения
и общий VPN сохраняют работоспособность.

## Дополнения владельца: интерфейс и производительность

Критерии дополняют исходное ТЗ, не изменяя его файл и профиль NF08.
Выполнение — в [статусе](current-stage.md), решения —
в [архитектуре](architecture.md#чтение-кэш-и-повтор-команд).

| ID | Критерий приёмки | Проверка |
| --- | --- | --- |
| U01 | Фильтры применяются сразу без «Применить», сбрасывают страницу и сохраняются в URL. Неверный период объясняется до запроса. Пагинация показывает общее число страниц/записей с учётом прав и фильтров. | UI-09, TC-08, TC-12 |
| U02 | Кэш обновляется после изменений; смена пользователя/роли очищает прежние данные до показа новой сессии. Повтор после потери ответа сохраняет ключ, результат и одну запись. | UI-10, UI-11, TC-02, TC-13 |
| U03 | В обоих Java-процессах HTTP использует virtual threads по умолчанию. fixedDelay-задачи сохраняют независимый прогресс, пулы БД и доставка ограничены. | TC-17, TC-05, TC-13; результаты опубликованной версии — в текущей стадии |
| U04 | LTS runtime и совместимые стабильные зависимости закреплены в сборке/lockfile. Обновления Node.js/Vite имеют свежую проверку генерации, типов, сборки и UI; изменение модели потоков — новый NF08. | SI-06.2, TC-15, TC-09, TC-13 |

«Большие нагрузки» не имеют отдельного числового SLA. Пройдены NF08 и
исследовательский TC-18 на 10 000 исходных записей и 20/40/80 клиентах;
версия, длительность, результаты и ограничения — в [текущей стадии](current-stage.md).
Это не доказательство непрерывного исполнения с такой скоростью. Приём задания и исполнение измеряются
раздельно. Кэш или virtual threads сами по себе не доказывают более высокую нагрузку.

| ID | Дополнительный критерий | Проверка |
| --- | --- | --- |
| U05 | Настройки памяти PostgreSQL соответствуют бюджету контейнера; SQL и индексы подтверждены планами на реалистичном наборе. Пулы соединений ограничены, права и точный подсчёт сохраняются. | SI-06.0, SI-06.4, TC-08, UI-09, TC-18 |
| U06 | Для повышенной нагрузки известны пределы API и обмена, очередь/возраст и восстановление после пика. Нагрузка не вызывает потери сохранённых команд, повторного исполнения или расширения доступа. | SI-06.5, TC-03–TC-05, TC-18 |

Расширенный профиль — исследование ёмкости, а не новое обещание SLA.
Его пределы, защитная остановка и непроверенные режимы отражаются в отчёте.
