## Владельцы и простота

- Domain/DTO валидирует сохраняемый текст; ошибка БД не подменяется общей 400.
- Protocol классифицирует ответ. Сохраняемые форматы Evidence/receipt и
  идентичность дедупликации не меняются ради текста диагностики.
- Обмен сохраняет одного владельца feed state; сеть вне транзакций.
  Backlog читается по запросу диагностики, без нового фонового процесса.
- HTTP correlation ограничен запросом, не переносится в глобальное состояние.
- Outbox, история, результат/cursor, пять попыток и права сохраняются.
- Без Redis, JPA, CI, generic CRUD, второго пула и legacy/fallback-путей.

## Проверки по срезам

Быстрые проверки касаются изменённого правила. Полная сборка/нагрузка —
один раз после интегрированного milestone. Изменившийся позднее участок
перепроверяется адресно, без повтора несвязанных gate.

BA-01: unit для U+0000 в разных позициях и допустимого Unicode; API
create/rename и разрешённых retry/resolve; нет частичных данных/receipt.
BA-03: ошибочные ответы, корректный соседний случай, исторические snapshots,
тот же/different fingerprint, потеря ответа и bounded body.
BA-04: ошибка/успех/rollback, разные запросы, clearing MDC, нет секретов.
BA-05: si.exchange.enabled принимает только true/false, точно совпадая с
ConditionalOnProperty; неподдерживаемые aliases отклоняются. Пустая/занятая
очередь, paused/unavailable/recovered feed, запрет
инициатору и anonymous; readiness не зависит от доступности исполнителя.
BA-06: управляемый concurrent commit между SELECT, без sleep-зависимой гонки.
BA-08: точная версия PostgreSQL и image labels, все ошибки и пропуски
в отчёте, после drain — исходные поля/результаты/история/cursor/one execution.

## PostgreSQL и выпуск

18.7 — patch в той же major-ветке. Проверить применимость примечаний к
индексам/расширениям; не запускать REINDEX или dump/restore автоматически.
Проверку upgrade делать только на собственном завершённом тестовом томе.
Обычный стенд и его данные не участвуют в reset/load/recovery.

При выпуске source, image, runtime и публичная приёмка — разные проверки.
Сначала подтвердить способ возврата конкретного patch. Не считать старый
тег гарантированным rollback БД. Без создания backups как побочного эффекта.

## Условные работы

- Быстрое внешнее исполнение: сначала существующие steady/external runner,
  arrival rate/backlog/возраст/throughput/locks/pool/CPU, затем адресная
  оптимизация. Нельзя выдумывать SLA или считать API p95 временем исполнения.
- Retention: документировать бессрочные receipts/identity; не удалять их
  без определённого срока replay и гарантии отсутствия повторного эффекта.
- Сессии/HA: один обычный instance остаётся поддерживаемой конфигурацией.
- Отдельный image security scan не заменять отсутствием matches в Maven OSV.

Исходное ТЗ не меняется. Generated outputs и подробные receipts — ignored.
