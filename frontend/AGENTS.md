# Frontend

React и TypeScript. Код сценария храните рядом с его экраном. Сервер
определяет доступ, статусы и доступные действия. Для REST используйте
клиент, сгенерированный из [внутреннего OpenAPI](../contracts/internal-api.openapi.yaml).

- Для общих полей и кнопок используйте локальные компоненты в src/shared/ui; новый компонент сначала ищите в Base. Не дублируйте их нативными элементами и глобальными стилями. Подключайте только используемые компоненты Base. Сохраняйте их происхождение
  и лицензию. Основной сценарий должен работать от 390 до 1440 px и с клавиатуры.
- Устанавливайте зависимости по lockfile и проверяйте сгенерированный
  клиент по [командам README](../README.md#сборка-и-проверки).

- Общие визуальные правила и состояния принадлежат src/shared/ui. На экранах используйте
  Card, PageHeader, FormField, Notice и другие существующие примитивы; CSS экрана
  определяет композицию, а не свою версию кнопок, полей или карточек.
- Brand в src/app/shell/brand.tsx используется на входе и в оболочке. Происхождение
  и адаптации компонентов перечислены в src/shared/ui/README.md.

- Внешний вертикальный интервал задаёт родительский base-page-stack. Не добавляйте
  margin одновременно в компонент и в контейнер; проверяйте загрузку, ошибку,
  пустое и заполненное состояние на обоих размерах экрана.

- URL владеет фильтрами и страницей: изменения применяются сразу без отправки.
  Кэш, отмена чтений и смена аккаунта описаны в
  [архитектуре](../docs/architecture.md#чтение-кэш-и-повтор-команд);
  при изменении правил проверяйте UI-09–UI-11.

Пагинация синхронизирует измеренный size только с текущим адресом. Маршрутизатор
может уже изменить браузерный URL до применения React-перехода; отложенный
эффект старой страницы не должен отменять новый маршрут или фильтр. Проверка
pathname/search/hash выполняется общим isCurrentLocation в pagination/collection;
не добавляйте задержки и локальные исключения в кнопки перехода.

До 760 px списки и история используют ленту с порциями по 20 записей,
прокруткой документа и IntersectionObserver. React Query владеет всей
последовательностью страниц через useCollection: maxPages=5, до 100 записей
в кэше/DOM и до пяти GET на refetch/poll. Не копируйте выдачу в state.
Предыдущие страницы доступны сверху; ошибка любого направления останавливает
autoload до явного retry. Фильтры остаются в URL, page/size принадлежат desktop.
Scroll position — небольшие sessionStorage metadata, изолированные userId/role
и коллекцией, без DTO. CollectionOwner передаёт только identity scope.
При изменении окна проверяйте оба направления, Back после Query GC, ошибки,
удалённый ID и высокий viewport; не заменяйте anchor одним numeric scrollY.


Зависимости направлены app → features → shared. App собирает providers/router/shell;
auth владеет сменой сессии и очисткой private cache, а QueryClient создаётся
в app/providers.tsx. Нижние слои не импортируют app. Tasks и operations владеют
своими query keys; task keys и task status labels — явные публичные входы
для обмена. Общие helpers находятся в shared/lib, tokens/controls/patterns —
в shared/styles. Возвращайте query proxy отдельно от items/meta; не копируйте
серверные записи в локальный state и не разворачивайте query result целиком.

Обычный build включает ESLint и строгий TypeScript с проверкой неиспользуемого
кода. Перед коммитом используйте lint/typecheck и затронутые tests; полный
build/test gate выполняется на интегрированном этапе. Negative lint fixtures
находятся в architecture-fixtures и выполняются только через test:api;
в production и общий lint src/tests они не входят. Type-only DTO imports
разрешены, generated requests принадлежат API, а URL parser получает только
канонический BusinessStatus enum. Narrow public paths закреплены в eslint.config.js.
StrictMode остаётся включённым; исправляйте cleanup/lifecycle, а не отключайте его.
