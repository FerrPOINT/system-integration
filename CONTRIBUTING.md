# Разработка

Запуск и зависимости описаны в [README](README.md#локальный-запуск).
Правила доступа и поведения — в [аналитике](docs/analysis.md),
границы кода — в [архитектуре](docs/architecture.md).
Для каждого модуля есть AGENTS.md с его владельцами и проверками.

- Начинайте с причины и владельца правила. Сохраняйте один актуальный контракт;
  не добавляйте слои, fallback или инфраструктуру без подтверждённой необходимости.
- При изменении REST обновляйте OpenAPI и потребителей согласованно.
  Сгенерированные интерфейсы, DTO и клиент появляются только в build.
- Используйте существующие компоненты и helpers. Новый экспорт, вариант или
  зависимость должны иметь реального потребителя.
- Изменяйте предметное правило вместе с проверкой на его публичной границе.
  Для SQL, транзакций и конкурентности используйте PostgreSQL; для интерфейса —
  существующие component/UI сценарии.
- Применённые миграции не переписывайте. Не меняйте схемы и хранимые форматы
  ради перестановки классов.
- Проверяйте ссылки, якоря и команды документации. Исторические планы находятся
  в [истории](docs/history.md); актуальное поведение задают владельческие документы.
- Включайте в commit только свои изменения. Секреты, зависимости, generated,
  build outputs и результаты прогонов оставляйте вне Git.
- Перед передачей укажите commit, выполненные проверки и границу публикации
  в [текущей стадии](docs/current-stage.md). Сборка и проверка публичной
  установки подтверждаются отдельно.

Проверка форматирования входит в build и не переписывает файлы автоматически.
Команды исправления стиля и проверки описаны в README.
