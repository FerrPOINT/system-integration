# Разработка

Подготовьте окружение и запустите каркас по [README](README.md#запуск-каркаса).
Перед изменением сверяйте задачу и её зависимости в
[декомпозиции](docs/decomposition.md). В `AGENTS.md` каждого рабочего
каталога описаны правила для его кода.

- Делайте связанные правки одним понятным изменением. Перед коммитом
  проверьте `git status` и включите только файлы своей задачи. Настройки
  окружения, результаты тестов и сгенерированный код оставляйте локально.
- При правке REST начните с OpenAPI. Проверьте сборку и контрактные тесты
  обеих сторон по [README](README.md#сборка-и-проверки). Для бизнес-правил,
  доступа и хранения выбирайте проверки из [плана приёмки](docs/test-cases.md).
- Для чистки документации проверьте ссылки, якоря и соответствие команд
  исходникам. При передаче изменения укажите версию и выполненные проверки
  в [текущей стадии](docs/current-stage.md).

## Применение стандартов Base

Используем актуальные команды из исходников, настройки через окружение,
проверки по границам приложения и журнал с идентификаторами операций.
Эти правила адаптированы из [стандартов Base](https://github.com/FerrPOINT/services-base/blob/0fafbb4b9073a06d54fefd9660eb58a8809bd66d/docs/REPO_STANDARDS.md),
[тестирования](https://github.com/FerrPOINT/services-base/blob/0fafbb4b9073a06d54fefd9660eb58a8809bd66d/docs/TESTING_STANDARD.md)
и [наблюдаемости](https://github.com/FerrPOINT/services-base/blob/0fafbb4b9073a06d54fefd9660eb58a8809bd66d/docs/OBSERVABILITY_STANDARD.md).
Требования, план, сценарии и подтверждения ведутся в `docs/`.
